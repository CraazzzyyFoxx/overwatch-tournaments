# Vendored fonts

`next/font/google` downloads font files from `fonts.gstatic.com` **during the
build**, at URLs whose hashes Google rotates. A production build died on four of
them returning `404` while the CSS naming them had just been fetched — the edge
serving that build host was handing out a CSS generation whose files had already
been purged. There is no retry or fallback for that failure: `next build` exits
non-zero, at the end of the image build, because of someone else's CDN.

These files remove the frontend build's only network dependency. They are
regenerated by hand, rarely — a font is a pinned asset, not a dependency.

## Sources

Upstream variable TTFs from [`github.com/google/fonts`][gf], all SIL OFL 1.1;
each family's licence sits beside its `.woff2` here, as the licence requires.

| File | Upstream |
| --- | --- |
| `inter-variable.woff2` | `ofl/inter/Inter[opsz,wght].ttf` |
| `onest-variable.woff2` | `ofl/onest/Onest[wght].ttf` |
| `onest-400.ttf`, `onest-700.ttf` | `ofl/onest/Onest[wght].ttf`, instanced |

[gf]: https://github.com/google/fonts

## Regenerating

```sh
pyftsubset "<Family>[wght].ttf" \
  --unicodes="U+0000-00FF,U+0131,U+0152-0153,U+02BB-02BC,U+02C6,U+02DA,U+02DC,U+0304,U+0308,U+0329,U+2000-206F,U+2074,U+20AC,U+2122,U+2191,U+2193,U+2212,U+2215,U+FEFF,U+FFFD,U+0100-017F,U+0301,U+0400-045F,U+0490-0491,U+04B0-04B1,U+2116" \
  --no-hinting --flavor=woff2 --output-file=<family>-variable.woff2
```

`fonttools[woff]` provides `pyftsubset`; the `[woff]` extra is what pulls in
brotli for the woff2 flavour. Both families take the same ranges.

The two `onest-*.ttf` are for Satori (`src/lib/og/encounter.tsx`), which
rasterizes OpenGraph cards outside the browser: it cannot read `woff2` and
cannot interpolate a variable axis, and the font `next/og` ships with has no
Cyrillic. Same ranges, one static instance per weight the card uses:

```sh
python -m fontTools.varLib.instancer "Onest[wght].ttf" wght=400 -o inst-400.ttf
python -m fontTools.subset inst-400.ttf --unicodes="<ranges above>" \
  --no-hinting --output-file=onest-400.ttf
```

## Why these ranges

`latin` and `cyrillic` are copied verbatim from the `unicode-range` descriptors
Google Fonts serves, so coverage matches what the site was already loading.
**Latin Extended-A** (`U+0100-017F`) is added on top: player and team names
carry `ł`, `ş`, `ğ` and `č`, and under the Google split those cost an extra
85 KB Inter file that only loaded once such a name appeared on screen.

Everything else Google ships is dropped deliberately — Greek, Vietnamese,
Cyrillic-Ext, and the phonetic half of `latin-ext` (`U+1D00-1DBF`,
`U+1E00-1E9F`, `U+2C60-2C7F`, `U+A720-A7FF`). That is ~130 KB of Inter alone
that no page here has ever rendered.

## Why one file per family, not Google's per-subset split

`next/font/local` has no way to express `unicode-range`, so a family is one
file. The trade was measured rather than assumed:

| | Google, per subset | Vendored |
| --- | --- | --- |
| Inter | 218,888 across 7 files | 94,852 |
| Onest | 64,632 across 4 files | 48,176 |
| **Total shipped** | **283,520** | **143,028** |

(JetBrains Mono, 48,396 B vendored, was retired in favour of Inter for the
data/label voice and the system monospace stack for code.)

A Cyrillic page used to fetch roughly 130 KB of that (the Latin and Cyrillic
subsets of each family), so the cost is about +55 KB always-loaded, against
three requests instead of eight, no build-time network call, and Latin
Extended-A included rather than a separate late fetch.

## Not `weight: ["500","600","700"]`

The old `Onest(...)` call named three static weights, which made Next ask Google
for static instances — the exact assets that 404'd. Both families here are
variable, declared with their `wght` axis span (`"100 900"`), so every weight
the design uses is interpolated from one file.
