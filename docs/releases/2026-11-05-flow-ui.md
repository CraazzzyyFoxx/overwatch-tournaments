# Tournament flow UI: release note

Organizers build and run a tournament from its flow graph: a new **Flow** tab in the admin section, with presets, live
validation and one save. Players get a **Table** tab (the leaderboard of a league season), a read-only **Format** tab,
a bracket grouped by flow branch and a register card per open registration. The release adds no migration.

## Wire changes

- New admin route: `POST /api/v1/admin/tournaments/{id}/flow/validate`, subject `rpc.tournament.flow_validate`. It
  needs the workspace `tournament.update` permission, takes a `FlowChanges` body and answers a dry run
  (`FlowValidationRead`: `issues`, the resolved `ports` of every node, `ref_ids`, `new_edge_ids`). It writes nothing
  and records no audit entry.
- `FlowNodeUpsert.stage`: a new `stage` node carries a `StageCreate`, and the save creates the stage. Deleting a
  `draft` stage node deletes its stage.
- `FlowRead.participants`: the names of the participants that the results of a flow refer to.
- `AdminFlowRead.config_defaults`: the seed config of each node kind, for the palette.
- Node config, node status moves (`POST /api/v1/admin/flow-nodes/{id}/transition`), node schedules and graph writes all
  need `tournament.update`. A role that only creates teams or tournaments cannot change a flow.
- `gateway/internal/openapi/schemas.json`, `frontend/src/types/api.generated.ts` and
  `frontend/e2e/support/route-table.ts` are regenerated (additions only).
- Removed with the flow: the public advance cut line (the "advances" marker) in group standings. Who advances is now a
  filter node's setting, and the standings do not draw a line from it.

## Known limits

- The cut line a filter implies is not drawn in group standings (see above); it is not part of this release.
- Filter `per_item` and `per_item_upper` overrides have no form; set them through `PUT …/flow`.
- A preset creates stages without items. Add the groups or the bracket in the stage's **Items** before moving it to
  **Ready**; the server refuses `draft → ready` for a stage without items.
- The balancer is a full-screen tool: the formation inspector links to it (`?tournament=<id>&node=<id>`) instead of
  embedding it.
- The editor does not check units or ports itself. The server's dry run is the only validator.
- `Tournament.team_formation` and `draft_format_json` stay; removing them needs its own plan.
- No per-node permissions, no check-in on stage nodes, no `rest` output on the filter.

## Migration and deploy

No migration. Deploy from one SHA in this order: tournament-service, gateway, frontend. The frontend calls the new
`flow/validate` route, so the gateway and tournament-service must be live first.
